Contributing
Thank you for your interest in this project. This is a specification and pre-registration project. The 24 build specifications are complete. The code has not been written yet. Contributions of any size are welcome.

Who can contribute
Anyone. You do not need a degree, an affiliation, or prior experience with this project. You need to be willing to read a specification carefully and build something that matches it, or to review a specification carefully and explain what is wrong with it.

Ways to contribute
Build a tool. Pick one of the 24 tools. Read its build specification. Build it. Open an issue first to say which one you are working on, so we do not have two people building the same thing.

Review a specification. Read one of the build specifications. If something is unclear, inconsistent, or wrong, open an issue describing the problem. Be specific. Point to the section and the sentence.

Test a tool. Once a tool exists, use it. Report bugs. Report unclear error messages. Report missing features.

Write documentation. Tutorials, examples, and guides are always needed.

Share the project. Tell someone who might be interested.

How to open an issue
Go to the Issues tab.

Click New issue.

Give it a short, specific title.

Describe what you want to do or what you found.

Submit.

If you are claiming a tool to build, say so in the issue. If you are reporting a bug, say what you did, what you expected, and what happened.

How to submit a pull request
Fork the repository.

Make your changes on a branch.

Open a pull request against the main branch.

Describe what you changed and why.

Be patient. A maintainer will review it.

What we are looking for
Correctness. The tool should match the specification.

Clarity. The code should be readable.

Reproducibility. The tool should produce the same output for the same input.

Tests. If the tool computes something, there should be a test that checks it.

Documentation. If the tool has a user interface, there should be instructions.

What we are not looking for
Rewrites of the specifications without discussion.

Changes that break the schema rules.

Changes that make a tool inconsistent with the specification.

Spam or self-promotion unrelated to the project.

Ground rules
Be constructive.

Be specific.

Be patient. This is a volunteer project.

No hostile readings. If something is unclear, ask.

No harassment of any kind.

Questions
If you have a question, open an issue. If you are unsure where to start, say so. Someone will help.
